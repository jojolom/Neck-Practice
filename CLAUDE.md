# Guitar Man

SwiftUI iOS app for guitar fretboard practice. On the device and in the app it is called **Guitar Man**.
The App Store name is **Guitar Man: Fretboard Trainer** (set on the 1.1 draft; 1.0 was published as "Neck Practice"). The bare name "Guitar Man" is already taken on the App Store, so the store name needs the descriptor while the home-screen name stays "Guitar Man" (`CFBundleDisplayName`).
Source files keep their `NeckPractice*` prefix, and the Xcode project, target, and folder are named "Guitar Man" — don't rename them; it would break signing and App Store continuity.

## Layout
- `Guitar Man.xcodeproj` — app target `Guitar Man` plus three Screen Time extension targets (below). Uses Xcode 16+ **file-system synchronized groups**: any `.swift` file placed in `Guitar Man/` is compiled automatically; never hand-edit `project.pbxproj` to add files.
- `Guitar Man/` — all source, flat (no subfolders). Files are prefixed by layer instead:
  - `NeckPracticeModels*.swift` — data + session logic (`@Observable` classes, SwiftData `@Model`s)
  - `NeckPracticeServices*.swift` — audio, pitch detection, metronome, looper, notifications
  - `NeckPracticeViews*.swift` — SwiftUI screens
  Follow this naming for new files.
- Staff notation: `NeckPracticeModelsNotation.swift` (`SpelledPitch`, `KeySignature`, `Interval`, `NoteValue`) and `NeckPracticeViewsStaffView.swift` (shared treble staff in guitar notation, written an octave above concert). Use these for anything shown on a staff; spell notes by letter, not `Note` (which can't tell F♯ from G♭).
- Compose (`NeckPracticeModelsComposition.swift`): chords are `PlacedChord`s (start beat, length 1–4 quarter beats, a `ChordSymbol`) in 4/4 or 3/4, 2–32 measures, with an optional `tempo` of its own; an optional melody is `MelodyNote`s on a timeline of ticks, twelve to a beat (`NoteValue.ticks`: a sixteenth is 3, a triplet eighth 4, an eighth 6). Plain notes sit on multiples of 3; a beat holding triplets (`isTripletBeat`) holds nothing else, and writing either kind over the other replaces that beat. A chord or note can be `tied` to the same one starting where it ends (`tiesForward`, `isTiedOver`; `struckChords`/`struckMelody` and `soundingBeats`/`soundingTicks` are what playback, Play Along and TAB use). `place`/`placeNote` shorten to fit before the next item/barline, gaps are `rests(inMeasure:)`/`melodyRests(inMeasure:)`, and every measure must add up (fuzzed in `chord-check`). Whole measures are copied, pasted, repeated, moved, inserted and deleted through `MeasureContent`/`Clip`; `setKey(root:isMinor:)` changes the key and moves the melody with it (don't set `keyRoot`/`isMinor` directly on a piece that may have a melody). It decodes the old one-note-value `slots` format, chords saved as bare degrees and melodies saved in eighths (`melody`), and still writes each chord's `degree` and an eighths-only `melody` beside the full `notes`, so older app versions can read new saves (without sixteenths, triplets or ties, which they then drop if they save).
  - `NeckPracticeModelsChord.swift`: `ChordSymbol` (degree, ♭/♯ shift, `ChordKind`, secondary dominant, inversion) and `CompositionChord` (spelling, numeral, name, notes); the palette's per-degree variants and the borrowed/secondary page. `NeckPracticeModelsCompositionTemplates.swift` and `NeckPracticeModelsCompositionExamples.swift`: Compose ▸ Examples (`CompositionExample.all`, in four levels): progressions, tunes with melodies written in a short text notation (`Composition.write(melody:)`), and advanced pieces. Only traditional or public-domain tunes get melodies; progressions behind modern songs are chords only. `chord-check` verifies every example builds exactly as written, so add new ones there by just adding to the list. `NeckPracticeModelsChordVoicing.swift`: chord shapes found by search (checked in `voicing-check`), drawn by `NeckPracticeViewsChordDiagramView.swift`.
  - The editor (`CompositionEditorView` in `NeckPracticeViewsCompositionView.swift`) types at a cursor from a pinned palette (chords or notes, lengths, Rest, backspace) and changes things by selection: tapping a chord, note or measure number on the staff swaps the palette for that selection's panel. Nothing is on a long-press, and anything that writes over or removes measures with music in them confirms first; keep both rules for new editing features. Undo/Redo are in the navigation bar. The bottom bar has Play (the whole piece, the selected measures, or from the selected chord or note), loop, tempo (kept per piece) and Play Along; `CompositionPlayer` does the playing (chords Together, Arpeggio, or Strummed/Fingerpicked with Solo Buddy's `SoloGroove.hits(for:style:)` patterns) and `audition` sounds what's tapped. The staff (`CompositionStaffView`) speaks to the editor in ticks and draws melody by time (`position(ofTick:in:)`, in columns `columnTicks(inMeasure:)` wide). Open in Solo Buddy (⋯ menu) makes a `SoloGroove` from the chord each measure starts on (`Composition.soloGroove`) and shows `SoloBuddyView(groove:onClose:)` as a full-screen cover: a `navigationDestination(isPresented:)` here pops Home's path-driven stack.
  - Writing by playing (the editor's Listen input): `CompositionScribe` (`NeckPracticeServicesCompositionScribe.swift`) listens through `ChordListener` (with `tracksPitch`) and `ComposeHearing` (`NeckPracticeModelsCompositionHearing.swift`, no UI) names what it hears: a chord is the best fit among the chords Compose offers in the key, a note is `PitchAnalyzer`'s pitch (wide range, `anyString`) when the chroma agrees. `NoteTracker`/`ChordTracker` write one thing per pluck or strum. Step by Step writes at the cursor; In Time records a take against a count-in and `Composition.write(chords:/notes:fromMeasure:)` puts it on the nearest beats. The click only runs through a take on headphones (the mic would hear it). All of it is checked in `chord-check` on synthetic strums; it can't be tried in the Simulator with a guitar, so changes to thresholds need a real device.
  - Melody can also be tapped on `ComposeFretboard`, and `CompositionTabRow` draws TAB under melody lines (both in `NeckPracticeViewsComposeInput.swift`); a `MelodyNote` remembers its `string` when entered on the fretboard, else `tabPosition(of:)` picks the lowest fret.
  - Sharing (`NeckPracticeViewsCompositionSharing.swift`): `ComposeShareView` (editor ⋯ menu, and a saved composition's swipe/context menu) offers a PDF lead sheet (`CompositionLeadSheet`: the read-only `CompositionStaffView` paged for US Letter with `measuresToALine`/`shownMeasures`, rendered with `ImageRenderer`) and a composition file. `CompositionFile` (`NeckPracticeModelsCompositionFile.swift`, no UI, checked in `chord-check`) is the `.guitarman` format: the saved composition in a versioned envelope; reading never trusts the file and always yields a new composition. The type `test.guitar-man.composition` is declared in `Guitar Man-Info.plist` at the repo root, which the app target merges into its generated Info.plist (`INFOPLIST_FILE`); keep it outside `Guitar Man/` so it isn't compiled as a resource. A file opened from another app arrives at `onOpenURL` in `NeckPracticeApp.swift` → `CompositionImport.open` → `DeepLinkRouter.openCompose`, and Home goes to Compose, whose list shows a notice (not an alert, which is lost if a sheet is up). `CompositionStore.shared` is the one store.
- Compose Settings (editor ⋯ menu, `ComposeSettingsView` in `NeckPracticeViewsComposeWalkthrough.swift`): Sound as You Write, chords Together/Arpeggio, count-in (`CompositionPlayer` keys in UserDefaults), Chords Under the Melody, TAB Under the Melody, and the Compose tour (`ComposeTour`: a coach-mark overlay that opens with the first composition opened each launch until turned off; editor parts mark themselves with `composeTourTarget(_:)`).
- Solo Buddy (`NeckPracticeModelsSoloBuddy.swift`, `NeckPracticeServicesBackingTrack.swift`, `NeckPracticeViewsSoloBuddyView.swift`): a looping backing track. `SoloGroove` (key, 1–4 `ChordSymbol`s, `BackingStyle`, tempo) turns each bar into `Hit`s played on the chord's `ChordVoicing` shape; `BackingTrack` hands bars from any `BackingSource` to `AudioPlayer.play(_:fromFrame:)` just ahead of time via `BarClock`; a change you'd hear (`soundsDifferent`, on any `BackingSource`) restarts the bar you're in from its first beat, within 30 ms. Presets are `SoloPreset.all`; saved grooves are `SavedGrooves` (UserDefaults), all reached from the Grooves sheet. Checked by `solo-buddy-check`. The metronome click lives in `NeckPracticeServicesClickSound.swift` (shared by Metronome and AudioPlayer's click voice).
- Blues Buddy (`NeckPracticeModelsBluesBuddy.swift`, `NeckPracticeViewsBluesBuddyView.swift`): all the blues lives here, not in Solo Buddy. `BluesGroove` (key, `BluesForm`, `BluesFeel`, tempo, and switches for bass picking, chord stabs and fills) makes up every bar from a seed and the bar's number (`bar(_:seed:)`, dice in `BluesDice`, one per layer), so no two takes are alike but a seed always replays the same; `BluesBacking` (groove + seed, a new seed each Play) is what `BackingTrack` plays. Presets are `BluesPreset.all`, saved grooves `SavedBluesGrooves`, which also takes over 12-bar grooves saved by Solo Buddy when it had that form (`SoloForm.twelveBar` is kept only to read them). Any bar's chord can be changed by tapping it in the bar chart (`changes`, bar → `ChordSymbol`, via `setChord(_:atBar:)`; another form or Reset drops them): the bass, stabs, fills and follow rules all go by `chord(forBar:)`, never by the form's degrees, and the key's major pentatonic is used where `takesMajorPentatonic(bar:)` says. The fretboard (`BluesFretboard`, from `fretboard(position:bar:)`) shows a `BluesScale` (minor, major, blues, or both pentatonics with the differing notes marked) in the neck area of the key's minor box at that position, whatever its root, so switching scales doesn't move the hand; with `followsChords` it changes per bar by a `BluesFollowRule`, and fills are made from what shows. `FretboardView` takes `customColors` and `focusFrets` for this. Trade Licks (`mode == .trade`) alternates turns of `tradeBars` bars: in Buddy's it plays a lick (`LickNote`s made from the dots showing at the position, top four strings) over a thinned backing, and `BluesBacking.cues` hands the notes to `BackingTrack`, whose `cue` names the one sounding so the screen can light it. Checked by `blues-buddy-check`.
- Theory Basics (`NeckPracticeModelsTheoryQuiz.swift`, `NeckPracticeViewsTheoryQuizView.swift`): multiple-choice theory questions from topics toggled in its Settings. Every key is a `KeySignature` + major/minor (`TheoryKey`), so names come out spelled by signature; `theory-quiz-check` verifies every question against independently worked-out theory. Add new question kinds there too.
- Settings stick and apply at once, in every game. A game's settings are its `*StepConfig` (`NeckPracticeModelsStepConfig.swift`: `settings` reads them from the session, `apply(override:)` puts them back; checked by `settings-check`). `.savesSettings(session.settings, game:, step:)` (`NeckPracticeViewsSavedSettings.swift`) saves on every change: to `settings.<game>` from the home screen, or to the plan's step in Daily Practice, so the two stay separate. The game then replaces the question only if `currentFitsSettings` is false; otherwise it stays and things like the number of choices update in place. New games and new settings should do the same (add new settings to the config too). `@SavedSetting("key")` is `@State` that's kept between launches, for screens with no settings sheet. Compose playback restarts the measure you're in on any change (`CompositionPlayer.restartMeasure`); the metronome changes tempo and subdivisions from its next unqueued click, without stopping. Count-ins (Solo Buddy's optional one, the Looper's) stay on purpose.
- Games with right/wrong answers hand their after-answer step to a `NextGate` (`NeckPracticeModelsAnswerPacing.swift`) instead of a timer, and show `NextButton` under the answers; the shared After Answering setting (`AnswerPacingSection`, in each game's Settings) picks Wait for Next (default), Wait After Mistakes, or Move On by Itself. New games should do the same.
- Note playback: `AudioPlayer` (`NeckPracticeServicesAudioPlayer.swift`) schedules every note on one sample-accurate timeline (`play([ScheduledNote])`). Voices: the recorded nylon guitar (`NeckPracticeServicesGuitarSamples.swift`, files in `Guitar Man/GuitarSamples/`, preloaded at launch) and the synthesized string fallback (`NeckPracticeServicesPluckedString.swift`). The recordings are the FreePats Spanish Classical Guitar (CC0, credited in About), rebuilt with `scripts/build-guitar-samples.swift` (trims, levels, measures each note's tuning into `nylon-guitar.json`); don't hand-edit the `.caf` files.
- `scripts/*-check.swift` — offline logic checks (theory, tuner, metronome, looper library, chords, chord shapes, note synth, guitar samples, scale study, Solo Buddy, Blues Buddy, theory quiz, settings). Each file's header has the `swiftc` command; model/analyzer files they compile must stay free of SwiftUI/UIKit.
- Screen Time ("Block apps until I practice") — needs the Family Controls entitlement and the App Group `group.test.Guitar-Man`:
  - `DeviceActivityMonitor/`, `ShieldConfiguration/`, `ShieldAction/` — one extension target each (`test.Guitar-Man.<Name>`), embedded in the app. Each folder holds its Swift file, `Info.plist` (excluded from the target's sources), and `.entitlements`.
  - `ScreenTimeShared/ScreenTimeShared.swift` — compiled into the app **and** all three extensions: App Group state, shield apply/clear, the 15-min unlock (2/day). Keep it plain, `nonisolated` code (the app target defaults to MainActor, the extensions don't). `appName` there is the name shown on the shield.
  - App side: `NeckPracticeServicesScreenTime.swift` (`ScreenTimeBlocker`) and `NeckPracticeViewsBlockAppsView.swift`. Screen Time only works on a real device, not the Simulator.
- `docs/index.html` — Support & Privacy Policy page, served by GitHub Pages at https://jojolom.github.io/Neck-Practice/ (the App Store listing's support/privacy URL). Keep it accurate when the app's data handling changes.
- `NeckPracticeApp.swift` — entry point; SwiftData container for `PracticeSessionLog`, injects `AudioSettings` via `.environment`. Also takes composition files opened from other apps (`onOpenURL`).

## Stack
Swift 5, SwiftUI, Observation (`@Observable`), SwiftData, AVFoundation, Accelerate (pitch detection), UserNotifications. iOS deployment target 26.2. One third-party dependency: TelemetryDeck (Swift package, anonymous usage analytics), used only through `Analytics` in `NeckPracticeServicesAnalytics.swift`; its App ID lives there. If what's sent changes, update the privacy policy in `docs/index.html` and the App Store privacy label.

## Build & run
```bash
xcodebuild -project "Guitar Man.xcodeproj" -scheme "Guitar Man" -destination 'generic/platform=iOS Simulator' build
```
Requires `xcode-select` to point at Xcode.app (not CommandLineTools).

## Release
- Add an entry at the top of `Changelog.entries` (`NeckPracticeModelsChangelog.swift`) for each new version — it drives the post-update "What's New" sheet and About ▸ Version History.
- Bump `MARKETING_VERSION` (user-facing version) in the target's build settings for each new App Store version; the build number is set automatically by the upload script.
- Upload to TestFlight with `scripts/upload-testflight.sh` (archives, signs via App Store Connect API key, uploads; build number = timestamp). API key config lives outside the repo in `~/.appstoreconnect/` — never copy it into the project or print it.
- Export signing is manual (`scripts/ExportOptions.plist`): the "Apple Distribution" certificate in Joe's login keychain plus four App Store profiles named "Guitar Man … App Store" (app + 3 extensions). The API key can't use Apple's cloud-managed certificate, so don't switch back to automatic. Certificate and profiles expire 2027-10-05; recreate the profiles with `scripts/asc.py POST /v1/profiles`. A new extension target needs its own profile in that plist.
- Uploading, submitting for App Review, and releasing are outward-facing: confirm with Joe before each one.
- Do not change `PRODUCT_BUNDLE_IDENTIFIER` or `DEVELOPMENT_TEAM` — the live App Store listing depends on them.
